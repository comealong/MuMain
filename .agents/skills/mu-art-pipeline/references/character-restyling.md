# 角色重塑、关节连接与动态蒙皮

适用于改变身体比例之后的造型、手掌、关节、接缝、纹理及播放变形问题。通用方法保存在这里；单个模型的配置、动作/关键帧、实验代码、截图和结果留在对应工作区。

## 选择输入阶段

- 原始恢复从原始资源开始，保留身体分件与共同骨架，见 [参考空间与贴图](character-model-assembly-and-textures.md)。
- 明确改比例时，先建立新旧骨架和网格的对应关系，见 [比例与动作复用](character-proportions-and-animation-reuse.md)。
- 已有重塑成果的局部问题，从确定的保存版本继续；确认哪些比例和参考变换已经应用，避免重复。

不要仅凭对象/材质名字划分解剖区域。一件躯干装备可能包含上臂，一件手套可能包含前臂；区域选择需依据实际几何、骨骼绑定及客户端槽位。

## 从设计到表面

风格重塑需要视觉参考时，先截图真实原模型，再生成或选择概念图，用它确认头身比、肩线、四肢、手掌、鞋与角色识别特征。概念图用于设计，不是三维拓扑或 UV atlas；制作贴图需另对 UV 岛布局提出约束。

先用灰模判断正面、侧面与三分之四轮廓，再精修材质和纹理。每次局部修订明确症状、原因假设、变化范围和判定视角；反复出现的症状应转查坐标空间、骨架、表面结构或绑定。

对显式允许重塑拓扑的身体，可从构造体生成统一外壳、清理内部面，再按需要拆回槽位。原始恢复、刚体盔甲、独立服装层及透明表面不默认走融合路径。体素分辨率依据最小需要保留的截面与细节选择，融合后重新检查指间结构和关节体积。

## 肩胸、手臂与手掌

### 解剖关系先于补缝

肩部要形成胸廓到上臂的过渡：肩线适度下降，肩峰与上臂体积相接，腋窝保留合理凹入。单独肩球加粗圆柱容易像外挂肢体；推入躯干能遮住缝，但不能自动得到自然肩线。

先确认肩、肘、腕位置和上下臂长度，再构造由胸廓内部开始，经肩帽、上臂、肘、腕的连续路径。根部端盖不要露在胸廓外；扫掠截面要沿路径变化，腕部有明确收细。过低的肩根会形成弯钩，过高的端盖会形成凸片，增加平滑次数不能替代包络修正。

左右手在参考姿态中的前后位置可能不同。同时看两侧和侧面，不能仅根据正面投影判定长度，也不能只镜像世界坐标就认定掌面正确。

### 掌体积和握持

建立手的局部正交坐标系，分别控制掌长、掌宽和掌厚，以及拇指根、四指与腕部层次。三轴体积可表达为：

~~~text
p = center
  + axis_length * radius_length * cos(theta)
  + sin(theta) * (axis_width * radius_width * cos(phi)
                + axis_thickness * radius_thickness * sin(phi))
~~~

轴向参数必须实际参与构造；仅把三条轴传给单轴扫掠函数，不会自动得到三轴朝向。手指可沿多控制点曲线逐渐收细，先确认指根和拇指侧别再提高分辨率。

持物手围绕实际物品姿态下的柄轴安排掌面、四指和拇指；空手沿腕部自然延伸，保持微曲与厚度。纯黑材质会掩盖掌指结构，应使用可读的明暗检查。指体全部绑定手骨只能跟随手整体运动；需要张手、握拳时，要另建立相应指骨绑定与动作。

挂点变换正确、掌部接触正确和双手配合正确是不同目标，见 [刚体挂接](weapon-attachment.md)。

## 膝、踝与连续截面

大腿与小腿各自封端、再在关节点相接，可能留下角度不同的楔形缺口；靴筒只触到鞋顶时，融合可能留下很薄的连接。即使表面拓扑已经连通，这些轮廓问题仍存在。

重塑时可使用髋到膝、踝及鞋内点的连续路径，在关节采用内部截面；需要重合的靴筒延伸进入鞋体后再处理外壳。装饰性靴口若是同一连续外壳上的颜色区域，可以用材质边界表达；真正独立的装备结构仍需保留其几何与绑定语义。

侧面、低角度及弯曲姿态要看关节最细截面和相邻肢体的相对体积。不要仅凭“一个连通分量、没有开口边”宣布连接自然，也不要无限放大鞋来遮住踝部问题。

## 分件边界与表面内部

拆分来自同一外壳的身体部件时，共享位置、绑定和需要连续的法线应来自同一份数据，并保留稳定的源顶点身份，例如 `mu_connected_source_vertex`。保持独立对象不妨碍共同边界使用相同数据。

- 静置位置一致，权重不同：动作中可能开缝。
- 位置与权重一致，法线不同：可能出现明暗断线。
- 边界数据全一致，表面内部邻点权重急变：动作中仍可能出现扇形尖刺或折叠。
- 表面拓扑封闭：不能据此排除薄桥、内部面、自相交或体积不足。

共享身份必须代表同一解剖表面位置；不要把不同服装层或空间中偶然重合的点误当作同一顶点。缺少身份时先重建可靠对应，不在无法配对的部件上独立平滑后假设它们一致。

## 动态肩腋和局部权重修复

### 诊断顺序

取得实际故障动作、帧与子帧，再用同一镜头比较贴图、灰模和相邻姿态。若灰模也有尖刺，检查参考空间、静置矩阵、绑定与邻接；若只有图案异常，查 UV、材质及边界采样。

从多个重叠构造体向融合外壳传递权重时，最近源面可能在邻点间切换，内部封端或交叉体积也可能参与查询。权重归一化和少量邻域平滑不保证足够连续；“接缝误差为零”只描述部件边界。

可以观察：

~~~text
weight_gradient(i,j) = ||w_i - w_j||_1 / ||p_i - p_j||
edge_stretch(i,j,k) = posed_edge_length(k) / rest_edge_length
~~~

梯度依赖模型尺度；拉伸比也受局部截面、采样密度和极短边影响。对相同区域做前后比较，并查看实际形状；不能把某个样例的峰值或分位数当成通用验收阈值。零长度/退化边要单独处理。

### 沿统一外壳求平滑权重

当问题来自不连续的初始绑定，可在身体共同外壳的邻接图上修复，保留胸部内侧、稳定远端肢体、握持和其它无需变化的区域作为固定边界。刚体装甲与需要硬绑定的区域应按其结构另外处理，不按材质标签一概混合。

对于自由顶点 U、固定点 F 及正导通系数 c_ij，可求解：

~~~text
minimize  E = sum_(i,j in edges) c_ij * ||w_i - w_j||²
subject to w_i = known_binding_i, i in F
~~~

c_ij 可与边长成反比，并用与尺度相适应的边长下限避免退化值。固定区域必须有可靠绑定；自由区域每个连通分量要连接到固定边界，否则解不唯一。未知点、固定点和可参与的骨骼通道由目标解剖与源绑定决定，不使用写死的世界坐标或节点。

可以迭代平滑或求解加权拉普拉斯的 Dirichlet 系统。使用共轭梯度等方法时，检查正定条件、残差和收敛状态；用完迭代上限不等于已经收敛。平滑范围与阈值按目标尺度、网格密度和需要保留的动作细节配置。

归一化后按同一源身份写回所有分件副本，再检查邻点梯度、变形拉伸及边界一致性。对于新外壳，优先在拆分前完成绑定；对于既有分件，按可靠共同身份操作。固定区的权重应保持，避免关节修复改变手掌握柄或其它已稳定部位。

### 蒙皮模式与表面修正

LBS 和 Preserve Volume/DQS 影响扭转和体积。用相同姿态对照两者，有助于区分算法效果与错误权重；切换模式不能普遍替代绑定修复。

若绑定已连续但极限姿态仍塌陷或碰撞，才进一步判断是否需要局部重塑、关节拓扑、姿态修正或其它变形方案。只在某个已求值帧平滑网格，不能修复整个动作。

## 重叠、UV 与纹理

先通过隐藏部件、线框和截面确认异常来自重复对象、内部重叠面、接近的服装层还是表面轮廓。关闭视口线框只改变显示，不会清除真实 Z-fighting。

颜色异常与几何异常分别检查。缺图像、UV 退化为一点、裤靴采样落到错误的图集区域，都可能产生平黑或错误颜色。先确定材质角色与外壳边界，再处理连续 UV；贴图生成应保留岛的功能布局。大头会放大脸部和发际的 UV 缺陷。

对照镜头、光照和色彩设置保持一致，并检查用户实际使用的视口模式。保存时打包使用中的纹理；美术原型的图像尺寸与客户端约束须分别验证。

## 通用脚本与调用契约

以下模块不打开或保存场景，不内置模型路径、节点号、动作号或身体坐标。前两项依赖 NumPy；Blender 适配层在 Blender Python 中使用。将 skill 的 scripts 加入模块搜索路径后，以 mu_art_pipeline 包导入。

| 模块 | 功能 | 调用方提供 |
| --- | --- | --- |
| [anatomical_surface.py](../scripts/mu_art_pipeline/anatomical_surface.py) | Catmull–Rom 路径、连续截面扫掠、三轴椭球 | 路径、截面尺寸、局部轴、采样数及端盖选择 |
| [surface_weights.py](../scripts/mu_art_pipeline/surface_weights.py) | 固定边界的加权拉普拉斯求解、权重梯度与边长拉伸指标 | 统一表面、完整绑定通道、自由区掩码、尺度对应的边长下限 |
| [blender_surface_binding.py](../scripts/mu_art_pipeline/blender_surface_binding.py) | 收集分件的共享表面、一致写回权重、测量求值接缝 | 明确的对象列表、绑定组名称、共同参考空间及对应误差容限 |

共享权重修复按以下顺序调用；所有变量来自当前目标的准备步骤：

~~~python
from mu_art_pipeline.blender_surface_binding import read_shared_surface, write_shared_weights
from mu_art_pipeline.surface_weights import solve_surface_weights

surface = read_shared_surface(
    parts, binding_groups, space_matrix=reference_frame,
    position_tolerance=position_tolerance, weight_tolerance=weight_tolerance,
)
repaired, report = solve_surface_weights(
    surface['coordinates'], surface['weights'], surface['edges'], free_mask,
    min_edge_length=minimum_edge_length,
)
write_shared_weights(parts, surface, repaired, free_mask)
~~~

- reference_frame 是共同参考坐标系到世界的矩阵；收集器把各对象局部位置转入该坐标系。free_mask 的顺序对应 surface['identities'] 的排序，不能直接套用某个分件的顶点序号。
- 绑定组必须覆盖完整的变形权重，并排除非绑定掩码组。求解不改变固定行；写回仅处理掩码选中的顶点及指定绑定组，保留其它组。共享身份和输入权重错误会拒绝处理；写回前检查所有目标对象的身份。
- 每个自由连通分量必须连接固定边界。求解检查残差和迭代上限，未收敛会报错；报告中的残差描述裁剪、归一化之前的线性系统。
- 生成表面返回顶点和面；扫掠还返回环索引。调用方负责解剖布置、壳体融合、共享身份、绑定、材质、UV 与槽位分配。曲线可能过冲或自交，不能把构造体当作已完成的角色。
- evaluated_seams 要求求值网格保留原顶点身份与对应顺序；改变拓扑后须重新建立对应。它只测量共享位置，不验证法线、表面内部变形、自相交或握持接触。

## Blender 工具经验

- 编辑骨架前明确活动对象与选择范围，避免改到对照骨架。
- 切到相容的视口 shading 类型后再指定对应 studio light；不同模式的枚举取值不一定相同。
- 应用修改器后旧 VertexGroup 引用可能失效，按名称重新取当前对象。
- 材质节点按类型或保存的引用识别，避免依赖本地化显示名称。
- 复用模块前检查导入副作用；某些实验入口会在导入时解析参数或确定输出目录。
- 检查求值网格时及时释放临时 mesh；大数组/JSON 不要逐字符写入界面文本。

## 检查与知识归档

分别检查静置轮廓、关键动作、故障帧前后及必要的帧间抽样。结构指标、实际查看的图、接触、保存后状态和客户端验证是不同证据，不能互相替代。输入与输出指纹、真实动作/帧范围、参数、失败日志和最终成果属于对应实验报告。

后续写回 skill 时，提取“适用条件 → 原因与判别方法 → 可复用处理 → 证明范围”。具体模型文件、职业/装备、节点号、动作号、固定倍率、相机/坐标、运行数值及历史截图不进入通用指导；可执行工具的配置、输入映射和实际检查结果保存在工作区。
