# 角色恢复、参考空间与贴图

## 分件与共享骨架

恢复客户端角色时，先从加载与渲染代码确定目标资源、身体槽位及真正使用的骨架。身体分件保留为独立网格，共用同一套姿态；文件名、对象名或职业名不能代替资源映射。原始恢复保留形状、拓扑、UV、纹理字段和源节点，不默认融合身体。

从原始资源恢复几何；已授权的局部造型修订则从确定的已保存版本继续，避免把旧变形重复施加到新结果。暂存模块中的预置资源集合不代表任意角色配置，使用前核对目标的实际部件清单。

可复用代码位于 `scripts/mu_art_pipeline`：

| 模块 | 作用 |
| --- | --- |
| `character_sources.py` | 暂存与来源指纹；调用前确认其资源选择 |
| `poses.py` | 局部/全局姿态及使用节点的父链校验 |
| `blender_player_rig.py` | 共享骨架、参考矩阵、动作通道和源元数据 |
| `blender_player_meshes.py` | 身体网格、共同绑定、UV、图像与源属性 |
| `blender_character_preview.py` | 预览镜头和视口呈现 |

这些是实现入口，不保证已有预置组装脚本覆盖所有职业或装备。

## 参考姿态与坐标空间

明确输入顶点属于骨骼局部、共同参考、已求值姿态还是世界空间，并记录实际选择的参考动作/关键帧。参考姿态、初始显示姿态和导出姿态可以不同，不能默认为同一帧。

对于骨骼局部顶点，设 B_i 为 Blender 实际静置矩阵，L_i 为源动画局部矩阵，G_i 为其层级组合，使用列向量：

~~~text
L_i(k) = T(p_i(k)) Rz(z_i(k)) Ry(y_i(k)) Rx(x_i(k))
G_i(k) = G_parent(k) L_i(k)
v_rest = B_i v_local
basis_i(k) = inverse(B_i) B_parent L_i(k)
v_posed(k) = G_i(k) v_local
~~~

根骨的父矩阵为单位阵。BMD 的旋转角为弧度；其它客户端接口的角度单位需另查。以上 basis 关系要求相应的父子层级与缩放约定成立，应以源矩阵计算的顶点验证实际 Armature 结果。

使用实际 `matrix_local`，不要只比较准备赋值的矩阵。新建骨骼应建立有效的非零长度，再设置完整参考矩阵并复核朝向；旧网格看似正常，也可能由旧坐标换算抵消了骨架错误。

骨骼按 `mu_bmd_node` 等源元数据查找，不按 Blender 集合下标查找。校验使用节点的父链和矩阵语义；两个文件拥有相似名称或相同骨数，不能证明绑定兼容。

## 动作通道

保留源动作与关键帧元数据，转换时处理四元数符号连续性。源通道为逐关键帧采样时，不应无意加入曲线过冲。根位移锁定按客户端规则解释，不能当作“整个动作没有位移”。

动作索引、关键帧索引、Blender 帧号及实际播放秒数是不同量。操作方法见 [动作查询与时间约定](player-action-index.md)。完整导入动作数量不等于完整视觉检查。

大段源 JSON 宜通过文件载入 Blender Text；逐字符插入超长单行内容可能造成明显开销。保存来源属性时保留其坐标约定，不能让新拓扑沿用已失效的源顶点/面索引。

## UV 与纹理

本项目 BMD 与正常打开的 Blender 图片使用不同的 V 轴约定：

~~~text
BMD → Blender: (U, V) → (U, 1 - V)
Blender → BMD: (U, V) → (U, 1 - V)
~~~

在格式边界转换一次，图片保持原方向；不要同时翻 UV、图片与材质节点。贴图必须来自资源的纹理引用字段，不能按角色名字猜替代文件。

UV 是面角数据。同一顶点可能在不同面角使用不同 UV；从原资源恢复时先确认面序、角点索引和拓扑对应。无法对应的新拓扑应重新展开或投射，不能照搬旧面角数组。

`mu_bmd_uv_convention` 用于识别已转换的导入数据。旧场景缺少标记时，应确认旧导出兼容路径，再显式迁移或重新导入；不要用反复翻转猜测修复。检查图像连接、UV 岛覆盖和正背面图案，仅检查 UV 范围或图片是否存在不够。

## 法线与保存后检查

非等比变换的法线用逆转置并归一化；有 UV/材质硬边时保留面角法线语义。分件边界要检查实际变形后的法线和明暗，几何坐标吻合不证明光照正确。

保存后重开，确认各分件引用同一骨架、实际动作范围、源节点、图像打包以及要求的对照。以独立的源姿态计算验证顶点，避免用待检查实现自身的输出作为唯一依据。原始恢复、重塑后的多权重预览和可安装 BMD 的保证范围要分别记录在工作区报告。
